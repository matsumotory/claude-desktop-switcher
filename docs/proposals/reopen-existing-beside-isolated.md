# 完全分離環境を終了せず既存のClaudeを開き直す

## 背景

既存のClaudeを先に開けば完全分離環境を並べて使える一方、既存のClaudeが終了すると、残った完全分離環境が起動を妨げます。画面の事前判定、coreの切り替え判定、復元計画の3か所が、すべての起動中Claudeを一律に拒否しています。

調査した端末では、Claude自身のログに、Claudeを操作していない間の自動更新による終了が記録されていました。CSWの監視はプロセスを読み取るだけで、Claudeを終了させません。この変更はCSW側の復帰の妨げを解消します。

## ゴール

残っているClaudeがすべて既知の完全分離環境なら、既存のClaudeを通常の起動操作、再試行、トレイ、復元から開き直せるようにします。対象は完全分離環境を並べて使う利用者です。既存の起動経路と判定を小さく修正します。

## 設計原則

- `core_bug_fix_protocol`に従い、仕様から回帰テストを書き、修正前の失敗を確認します。
- セキュリティ・プライバシー・倫理を利便性と引き換えにしません。実行中のClaude、データ、資格情報、更新設定は変更しません。
- 例外は内部識別子`default`だけです。既存のClaudeの二重起動、共有・コピーを含む環境、不明なプロセス、空のプロセス情報は拒否します。
- 起動引数から環境を判断する既存の処理を使います。復元計画の後にもcoreで実際のプロセスを再確認します。

## リスクと対応

プロセス確認と起動の間の競合は従来からあります。既存のClaudeを含むプロセスや分類できないプロセスは安全側に拒否します。実際の利用を中断しないため、回帰テストには一時ディレクトリとモックを使い、Claudeの実機起動は行いません。

## スコープ外

Claude自身の自動更新やSquirrelの共有状態の変更、既存環境の終了、更新の自動適用、共有環境の同時起動は含めません。

## 検証結果

修正前のcoreテストは18件中2件が失敗し、既定への復帰と復元の不具合を検出しました。画面の起動分岐のアサーションも修正前に失敗しました。

修正後はワークスペースのfmt・clippy・buildが成功し、`cargo test --workspace`の130件が成功しました。画面の分岐4ケース、JavaScriptの構文、和文の検査と検査スクリプトの22テストも成功しました。独立したコードレビューと日英の整合性確認で、提出を妨げる問題は残っていません。

実行中のClaudeを維持するため、実機の起動・更新・共存は検証していません。


## レビュー指摘への追加対応

起動を許可する安全性の判定には、`ps`が空白で連結した表示文字列を使いません。macOSの`KERN_PROCARGS2`から引数の境界を保ったまま取得し、CSWが生成する`--user-data-dir=値`の完全一致だけを認めます。別の引数への埋め込み、値の接尾辞、重複指定、単一ハイフンの別名、空白の除去で意味が変わる指定は拒否します。`--type`の部分一致で候補を除外せず、既知の完全分離環境と確認できない候補は拒否します。取得失敗、空の結果、確認中のPID集合の変化も拒否します。確認後の新規プロセス起動との競合までは原子的に排除できません。

このmacOS APIは、OSや対象プロセスの制限状態によっては、引数に続く環境変数のバイト列も一時バッファへ返します。デコードは`argc`個の引数で止め、環境変数を解釈・返却・保存・ログ出力しません。一時バッファは使用後に通常のゼロ上書きをしますが、コンパイラ最適化に耐える安全な消去を保証するものではありません。

復元計画は未知の名前だけが起動中の場合も「起動中なし」と扱わず、既存のClaudeと共有環境の起動を拒否します。既知と未知が混在する場合も同様です。

追加した回帰テストは引数の境界と別名、切断・不正なネイティブバッファ、環境領域を返さないこと、未知の起動中環境を対象にします。この追加対応の作業環境にはRustツールチェーンがなく、ローカルのRED・GREEN、fmt、clippy、ビルドは未実施です。上記の提出時の検証結果とは区別し、追加コミットのGitHub Actionsで確認する必要があります。実行中のClaudeを対象にしたネイティブAPIの読取や実機起動も行っていません。
