## 背景とゴール

英語の変更説明を公開後の手動dispatchで追加する運用では、配布物が完成しても英語節が欠けたまま残る。担当エージェントが公開前に英語を保存し、CIが本文へ自動反映する。v0.24.7の既存本文も補完する。

## 設計と変更範囲

- `.github/release-notes/vX.Y.Z.en.md`に版を明記した英語を保存する。機械的な翻訳生成は行わない。
- `release_notes.py`が版と内容を検証し、日本語節・英語節・配布物説明を組み立てる。
- `publish_release_notes.py`が既存リリースの本文だけを書き、同じ本文を読み戻せたことを確認する。
- `release.yml`は公開前に検証し、アセットジョブの後に本文を反映する。
- `release-notes.yml`はmainの英語ファイル変更でも起動し、変更された版の既存本文だけを更新する。
- PRの検査と回帰テストを追加し、CLAUDE.mdとマージ手順を同期する。

## 原則とリスク対策

セキュリティ・プライバシー・倫理を利便性と引き換えにしない。新しい秘密情報、外部AI、権限の拡張は不要。書き込みは既存のcontents権限でリリース本文だけを対象とする。PRから書き込みジョブを実行しない。タグ・版・パスを厳密に確認し、英語をshellへ展開しない。古い版にファイルが無ければ更新対象にしない。

## スコープ外

アプリのコード、版上げ、タグの付け直し、公開済みバイナリの再ビルドと再添付、署名・公証設定、ブランチ保護は変更しない。

## 検証と完了条件

- [x] 新しい挙動のテストが実装前に失敗することを確認する。
- [x] 版不一致、英語欠落、空の本文の復元、重複防止、既存英語の訂正、日本語保持を検査する。
- [x] 既存リリースだけを更新し、PATCHがbody以外を送らないことを検査する。
- [ ] 独立レビューとPRのTest・Build・Lint・Security・英語ノート検査を通す。
- [ ] mainへのマージ後、v0.24.7本文に日英の変更説明と配布物説明があることを確認する。
- [ ] 公開済みアセットのID・digestとタグが変更されていないことを確認する。

Pythonの検証は`python3 -m unittest discover -s .github/scripts -p 'test_*release_notes.py' -v`と`python3 .github/scripts/release_notes.py --validate-current`で行う。アプリのRust検証は既存CIを確認する。今回の環境ではMac上の実機検証は行わない。
