# Codeタブの会話一覧を起動の前に環境へコピーする

## 背景

「アカウントだけ分ける」は会話の本体`projects/`を共有するので、ターミナルのClaude Codeでは同じ会話を続けられる。デスクトップアプリのCodeタブの会話一覧は、`claude-code-sessions/<accountUuid>/<organizationUuid>/`に記録`local_<id>.json`として置かれる。フォルダ名がアカウントごとに違うので、一覧は環境ごとに分かれる。リンクで共有すると、アプリはリンクを通して保存しないので、その環境で始めた会話が終了時に失われる。v0.24.8でこの不具合が起き、v0.25.0でリンクを取りやめた。

## 決めたこと

- CSWから環境を起動する直前に、一覧の記録を、その環境のアカウントのフォルダへ実ファイルとしてコピーする。コピー元は、既存のClaudeと、同じ共有元で会話履歴を共有するほかの環境である。「アカウントだけ分ける」の一部として行い、別の選択肢にはしない。
- 書き込むのは、起動する環境の側だけにする。既存のClaudeのデータフォルダには書き込まない。そのため、環境で始めた会話は既存のClaudeの一覧に出ない。既存のClaudeでは`claude --resume`で続けられる。
- 記録はバイト単位でそのままコピーし、中身を書き換えない。どちらの記録が新しいかを決めるために読むのは、`lastActivityAt`と`lastFocusedAt`の2つのフィールドだけにする。`docs/PRIVACY.md`と`docs/PRIVACY_EN.md`に、読むフィールドと、記録をそのまま写すことを書く。
- いまの起動時の処理と同じ守りを保つ。その環境のClaudeが起動中のときと、起動中かどうかを判定できないときは何もしない。既存のClaudeのデータフォルダの中では操作を拒否する。

## 実装の前に確かめること

2026-11-09に、このMacの既存のClaudeの記録318件について、キーとIDの出る場所を調べた。値は読んでいない。次の4点は、PRで試してテストに入れる。

- アカウントのIDは、どの記録の値にも出ない。organizationのIDは、61件の`dispatchParentId`に`local_ditto_<organizationUuid>`の形で出る。別のアカウントの環境では、この親の会話が存在しない。アプリがその記録をどう扱うかを確かめ、写すか除くかを決める。
- アーカイブの状態は、各記録の`isArchived`と、索引`archived-sessions.idx`の両方にある。アプリがどちらに従うかを確かめる。
- 91件の記録に`scheduledTaskId`がある。コピーは`scheduled-tasks.json`を写さないので、参照先の無い記録をアプリが受け付けるかを確かめる。
- 削除の印`deleted_<id>`はこのMacに無く、形式を確かめていない。実際に会話を削除して作った記録を、テストの入力にする。
